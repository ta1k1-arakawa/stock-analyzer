04なぜ止まったのか、そしてその厳格さは判定に影響しない

T0 を止めているのは1件のレビュー所見です。

V9_009_HIGH_2=FROZEN_JPX_CALENDAR_IS_NOT_MECHANICALLY_BOUND → OPEN_REQUIRES_HISTORICAL_JPX_CALENDAR_BINDING

レビュー合格基準が C=0/H=0/M=0 なので、HIGH が1件でも開いていると進めない。これが V9_010〜V9_014 のカスケード全体の起点です。手続きとしては筋が通っています。

ただし、この厳格さが T0 の判定を動かす余地はありません。

T0 の STOP 条件は実装上こうです。

# v9_009_t0_top1_kill_screen.py:770-773
ridge_stop    = ridge["aggregate"] <= 0    and ridge["positive_years"] <= 3
lightgbm_stop = lightgbm["aggregate"] <= 0 and lightgbm["positive_years"] <= 3
return "STOP" if ridge_stop and lightgbm_stop else "CONTINUE"

判定は 2020〜2025 の全D0の等重量平均（aggregate_top1_edge）と、6年中の正の年数で決まります。

  • 2020〜2025 の営業日は 約 1,446 日
  • 2020-10-01 はそのうち1日 = 0.07%
  • ターゲットが D1〜D3 なので、影響を受ける D0 を窓の重なりまで含めても 約4日 = 0.28%

1,446日中4日の扱いが、等重量平均の符号と「6年中4年以上プラス」を反転させることはありません。しかも T0 自身が evidential_capacity=ZERO と宣言する、STOP / CONTINUE の二値スクリーンです。判定に効かない精度のために、判定そのものが1週間止まっている状態です。

技術的な補足

T0 実装のカレンダーは引数注入（calendar_dates: Sequence[object]）です。コードは既に任意のカレンダーで走ります。HIGH_2 は provenance の要求であって、計算上の障害ではありません。

05プロジェクト自身のルールが既に答えを出している

V9_PREFREEZE_PROPORTIONAL_STRICTNESS_AND_F6_COVERAGE_AMENDMENT.md（status = HUMAN_AUTHORIZED）にこうあります。

strictness=STRICT_ON_INFERENCE_PRAGMATIC_ON_PLUMBING operating_rule=CLAIM_LEVEL_FAIL_CLOSED_PROJECT_LEVEL_GRACEFUL_DEGRADATION

For public source/data plumbing and coverage, inability to mechanically prove a cell/year/month leaves that claim MISSING/UNPROVEN. It does not by itself terminate V9 unless the missing evidence is indispensable to a frozen downstream inference. Severity tracks inferential/statistical irreversibility.

推論には厳格、配管には実用的 — これが人間承認済みの運用ルールです。取引カレンダーは配管 (plumbing) です。そして 1,446日中4日は、evidential_capacity=ZERO の二値スクリーンにとって indispensable to a frozen downstream inference ではありません。

つまり、2020-10-01 を UNPROVEN として落として T0 を走らせることは、プロセスを破ることではなく、このプロジェクトが既に自分で承認したルールを適用するだけです。

07設計自体は正しい方向にある

厳しく書きましたが、V9 の設計判断はこれまでの失敗を的確に吸収しています。ここは維持すべきです。

No optimistic stop-price execution model学習ラベルと実約定の不一致
measurement-first ロードマップ測る前に作り込む癖

過去の教訓は全部設計に入っています。入っていないのは「測る」という一手だけです。

08進むべき方向

カレンダーのカスケードを止めて、T0 を走らせる。いま必要なのは新しい successor study ではありません。1回の測定です。

  1. V9_014 を凍結する

    破棄せず PARKED として記録に残す。6,217行は消さない。ただしこれ以上増やさない。

  2. V9_009_HIGH_2 を比例的厳格さで閉じる

    V9_PREFREEZE_PROPORTIONAL_STRICTNESS を根拠に、次を事前登録してから実行する。

    • 2020-10-01 を UNPROVEN として記録（「非営業日と証明した」とは書かない）
    • D1〜D3 の窓が 2020-10-01 に重なる D0 を T0 の D0 グリッドから除外
    • 除外した D0 数を成果物に明記（約4日 / 約1,446日 = 0.28%）
    • この扱いは T0 限定。T1・正式評価・配備判断には持ち込まない
    • 落とした D0 数が判定を反転し得ないことを感度チェックとして併記

  3. T0 を実行する

    ネットワーク 0、有料データ 0、手元のキャッシュのみ。出力は STOP / CONTINUE / NO_VERDICT_DATA_INCOMPATIBLE の3値。

  4. 結果で分岐する

    STOP なら

    V9 のこの仮説を閉じる。カレンダー装置も J-Quants 月額も不要と確定。30万円のゴールに対しては、シグナル探索より「S株で買える価格帯の銘柄 × 単純ベースライン（等重量・ホールド）を上回れるか」という、より低い階段から組み直す。

    CONTINUE なら

    ここで初めてカレンダーと PIT / 上場廃止銘柄の整備に投資する根拠が立つ。V9_007 のロードマップどおりの順序に戻る。

  5. J-Quants を一旦解約する

    V9_011_RESULT=FAIL_TERMINAL で目的未達、T0 はこのデータを必要としない。年 13.2% のコストを、CONTINUE が出るまで止める。再契約は「CONTINUE が出て、かつ point-in-time データが本当に必要になった時点」。

やらないこと

  • 新しい successor study の設計（V9_015 …）— カスケードの延長になる
  • 2020-10-01 を「SOURCE_B で非活動と証明済み」と記録すること — 設計書が禁じており、実際に不可能
  • T0 の結果を見てから特徴量・モデル・閾値を調整すること — further_loop_on_same_data: PROHIBITED
  • 設計方針（S株・単一ポジション・pooled cross-sectional・必須ベースライン）の変更 — ここは正しい
