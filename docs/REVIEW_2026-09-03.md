# レビューと今後の方向性 (2026-09-03)

対象: 直近1週間のコミット (2026-08-27 〜 2026-09-03) と、それが積み上げた `data/trade_log_*.csv`。

前提となるゴール: **自動売買はしない。通知を受けて自分で買い、30万円の予算で利益を出す。**

---

## 1. 直近1週間に何が起きていたか

この1週間のコミットは6件、すべて GitHub Actions Bot の `Update trade log [skip ci]` です。
人の手が入った最後のコミットは **2026-07-26** (`直近の答え合わせを今日の売却結果に変更`)。
つまり **約6週間、コードは一切変わらず、ペーパートレードのログだけが自動で積み上がっている** 状態です。

コミットの中身は2種類しかありません。

- 新しい `PENDING` 行の追加 (= 買いシグナルが出た)
- 既存の `PENDING` 行が `DONE` に変わる (= 2営業日後に決済され、損益が確定した)

システムは設計どおり動いています。壊れてはいません。
**問題は「動いているものが、30万円で実行できる指示になっていない」ことです。**

## 3. 致命的な問題 3つ

### 🔴 P0-1: 単元株(100株)制約が実装されていない

`src/tracker.py` の株数計算:

```python
lots = max(int(self.budget / actual_buy_price), 1)   # ← 1株単位で計算している
```

日本株は **100株単位** でしか買えません。この計算だと:

| 銘柄 | 直近株価 | ログの想定株数 | 100株の必要額 | 30万で買えるか |
|---|---|---|---|---|
| 5020 ENEOS | 1,390円 | 215株 | 139,042円 | ✅ 200株まで |
| 7211 三菱自動車 | 370円 | 810株 | 37,031円 | ✅ 800株まで |
| 8306 三菱UFJ | 3,681円 | 81株 | **368,110円** | ❌ **予算超過** |

**8306 三菱UFJ は30万円では1単元も買えません。**
にもかかわらず 8306 は `backtest_selection.yaml` の `recommended_stock_code`、
シグナル数45件で全体の57%、通知対象。**累計+26,474円は丸ごと架空の数字です。**

### 🔴 P0-2: 資金が重複計上されている (最大150万円が前提)

シグナルはほぼ毎日出て、保有は2営業日。当然建玉が重なります。

- 銘柄ごとの最大同時保有: **2建玉**
- 全銘柄合計の最大同時保有: **5建玉** → **必要資金 約150万円**
- 平均同時保有: 2.1建玉 → 約63万円

ログは1シグナルごとに「予算30万を全額使う」独立計算をしているので、
**+69,014円は「30万×5口=150万を運用した場合」の数字**です。

### 🔴 P0-3: 売り通知が存在しない

`src/tracker.py` の `get_daily_report()` が返すのは2つだけ:

1. 📝 本日の答え合わせ (= **過去**の決済結果)
2. 📊 通算成績

**「今日この銘柄を売ってください」という通知がどこにもありません。**
買いシグナルで買った人は、いつ売るのか通知されないまま放置されます。
本日時点で `PENDING` = あなたが保有しているはずの建玉が5件ありますが、
その売却期限は通知に一切出てきません。

| シグナル日 | 銘柄 | prob | 売るべき日 |
|---|---|---|---|
| 2026-09-02 | 5020 ENEOS | 0.199 | シグナル日+2営業日の大引け |
| 2026-09-02 | 7211 三菱自動車 | 0.792 | 同 |
| 2026-09-03 | 7211 三菱自動車 | 0.581 | 同 |
| 2026-09-02 | 8306 三菱UFJ | 0.239 | 同 (そもそも買えない) |
| 2026-09-03 | 8306 三菱UFJ | 0.421 | 同 (そもそも買えない) |

**「通知が来て自分が買って利益を出す」というゴールに対して、ワークフローの後半が丸ごと欠けています。**

## 4. 30万円で現実に何が起きたか (再シミュレーション)

制約を入れ直して計算しました。条件: 資金30万円、100株単位、**同時に1建玉のみ**、シグナルは先着順。

```
執行できた取引 : 18件 / 候補 74件
  資金が塞がってスキップ : 19件
  100株が買えずスキップ  : 37件   ← ほぼ全部 8306
最終資金 : 330,061円
損益     : +30,061円 (+10.02%)
勝率     : 11/18 = 61.1%
```

**約3.5ヶ月で +30,061円 (+10.0%)。悪くありません。** 勝率も61%に上がっています。
ただしログ上の+69,014円の**半分以下**であり、候補74件のうち**執行できたのは18件だけ**です。

### ただし: 単純ホールドに負けています

| 銘柄 | 同期間の値動き | 30万でホールドしていたら |
|---|---|---|
| 8306 三菱UFJ | 3,011円 → 3,753円 (**+24.6%**) | (100株=30.1万でギリギリ) 約 **+74,200円** |
| 5020 ENEOS | 1,271円 → 1,347円 (+6.0%) | +15,196円 |
| 7211 三菱自動車 | 390円 → 375円 (-4.0%) | -10,871円 |

**8306 を5月末に100株買って放置するだけで +74,200円。** 戦略の+30,061円を大きく上回ります。
「AIシグナルで小刻みに売買する」ことが、**上昇トレンド銘柄を持ち続けるより不利になっている**。
これは評価指標に「ホールドとの比較」が無いために見えていなかった問題です。

## 5. シグナルが「シグナル」になっていない

| 銘柄 | threshold | 発火率 |
|---|---|---|
| 5020 ENEOS | 0.15 | 25回/36営業日 = **69%の日に発火** |
| 7211 三菱自動車 | 0.50 | 9回/36営業日 = 25% |
| 8306 三菱UFJ | 0.15 | 45回/72営業日 = **62%の日に発火** |

`threshold: 0.15` は実質「ほぼ毎日買え」です。8306 の prob 分布は中央値 0.368、
**45件中31件が prob < 0.5** — モデルが「上がらない」と言っている日に買っています。

確信度と結果の相関も、ほぼありません。

| 銘柄 | prob と損益率の相関 | prob高群 平均 | prob低群 平均 |
|---|---|---|---|
| 5020 | +0.083 | +0.594% | -0.128% |
| 7211 | +0.287 | +2.065% | +0.103% |
| 8306 | **-0.001** | +0.383% | +0.019% |

**8306 は相関ゼロ。** 確信度に情報量がない = 選別できていない。
7211 (threshold 0.5) だけは +0.287 とわずかに機能しており、
**閾値を上げた銘柄でだけ確信度が意味を持つ** という示唆になっています。

加えて `src/predict.py` は 様子見 (HOLD) の日も Slack に投げるので、
**3銘柄 × 毎営業日 = 毎日3通** が届きます。通知が多すぎて「本当に買う日」が埋もれます。

## 6. その他の指摘 (優先度中)

- **損切り価格の基準がズレている**。通知は当日終値ベースで `損切り目安` を出すが、
  実際の建値は翌日の寄付 (`actual_buy_price`)。値が飛べば損切りラインが変わります。
- **学習ラベルが損切りを考慮していない**。`src/analysis.py` のラベルは
  「T+2の終値が+1%以上か」だけ。実運用は STOP で途中降りするため、学習と執行が食い違っています。
- **手数料 0%**。SBI/楽天のゼロコースなら妥当ですが、明示的に前提として書いておくべきです。
- **`backtest_selection.yaml` が 2026-07-14 のまま**。約2ヶ月更新されておらず、
  Actions は `train.py` と `main.py` しか回していません (`backtest.py` は手動実行のみ)。
- **テストが `tests/test_tracker.py` の4件だけ**。株数計算のような金額に直結する箇所に
  テストがありません。P0-1 の見落としはこれが原因です。

## 7. 進むべき方向

### 結論

**「バックテストのスコアを上げる研究ツール」から「30万円で実行できる指示を出すアシスタント」に舵を切る。**

現状のシステムは前者として作られており、後者としては未完成です。
モデルの精度を上げる作業より、**執行可能性 (executability) を作り込む方が先** です。
理由は単純で、いまの成績表は30万円では再現できず、**精度を上げても再現できないままだから**です。

### Phase 1 — 「実行できる」状態にする (これを最優先)

1. **単元株(100株)対応**: `tracker.py` の株数計算を `int(budget // (price*100)) * 100` に修正
2. **予算で買えない銘柄を自動的に対象外にする**: `price × 100 > budget` なら通知・記録しない
   → **8306 三菱UFJ は `paper_trade: false` / `notify_slack: false` に落とす**
3. **資金管理を1本の口座として扱う**: 同時保有を予算内に制限し、建玉が埋まっていればシグナルを見送る
4. **売り通知を作る**: 保有中の建玉について「本日の大引けで売却」を通知する
5. **通知を実行可能な文面にする**: 銘柄 / **買う株数** / **概算必要額** / 「翌営業日の寄付で買い」 /
   「○月○日の大引けで売り」 / **建値ベースの損切り価格**

> 移行について: 現在のログは架空の株数で計算されているため、混在させると成績が読めなくなります。
> リポジトリに前例がある `data/archive/` に退避し、**新ルールで記録を作り直す**のが妥当です。
> (前例: `data/archive/2026-07-14_before_active_3/`)

### Phase 2 — 通知の質を上げる

6. **閾値を上げる**: 発火率を **2〜3割程度** に落とす。5020/8306 の `0.15` は低すぎます。
   7211 が唯一 prob と結果に相関 (+0.287) を持っているのは閾値 0.5 だからです。
7. **様子見(HOLD)通知をやめる**: 買う日・売る日だけ通知する。デフォルトは静かにする。
8. **買える銘柄を増やす**: 30万で100株買える価格帯 (〜3,000円) の銘柄に候補を寄せる。
   現状は候補8銘柄中、実質2銘柄しか執行できていません。

### Phase 3 — 評価をやり直す

9. **バックテストの評価指標に「単純ホールドとの比較」を必須で入れる**。
   ホールドに負ける戦略を PASS にしてはいけません (今回 8306 がまさにそれ)。
10. **`backtest.py` にも単元株制約と資金上限を入れる**。
    でなければ Phase 1 の修正後もバックテストだけ架空の数字を出し続けます。
11. **株数計算・資金管理・売却判定にテストを追加する**。金額に直結する箇所を守る。

### やらないこと

- 自動発注・証券APIとの連携 (ゴールは「自分で買う」)
- モデル・特徴量の改良 (Phase 1〜3 が終わるまで後回し。
  執行できない成績表の精度を上げても意味がない)

## 8. 次の一手

**Phase 1 の 1〜5 を実装する。** 具体的には:

- `src/tracker.py`: 単元株計算、資金管理
- `src/predict.py`: 予算チェック、売り通知、通知文面の書き換え
- `config.yaml`: 8306 を対象外へ
- `data/archive/`: 現行ログを退避して記録を作り直す
- `tests/`: 株数計算と資金管理のテスト追加

これで初めて「通知が来る → その通知どおりに30万円で買える → 売る日も通知される」という
ゴールの一連の流れが成立します。
