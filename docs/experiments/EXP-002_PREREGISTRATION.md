## 目的

EXP-001 までに、値動きだけを使った方法はどれも「買って持つだけ」に勝てなかった。
今回は値動き以外の情報として決算イベントを使い、文献上の根拠があってパラメータがほぼ無い案を2つだけ試す。

## 銘柄

`EXP-002_HANDOFF.md` のとおり、すでに V13 から除外済みの銘柄だけを使う。

- `V4_UNIVERSE.csv` の300銘柄（v13 ブランチ、SHA-256 `d40b1fcf…4c41997`、`V4_UNIVERSE_MANIFEST.json` と一致を確認）
- 旧8銘柄から ETF の 1570 を除いた7銘柄（4188, 4689, 5020, 7211, 7267, 8306, 9432。4188 は上の300銘柄と重複）
- 合計306銘柄。現在上場している銘柄だけなので、結果は生存者バイアスを含む

流動性の条件：開示日の前営業日までの20営業日の売買代金の平均が **1億円以上** のイベントだけを使う。
この1億円は V13 の流動性条件と同じ値で、今回新しく決めた値ではない。

## データ

- 株価：`/v2/equities/bars/daily?code=`（調整済みの始値 `AdjO`・終値 `AdjC`、流動性には売買代金 `Va`）
- 決算：`/v2/fins/summary?code=`（決算短信と業績予想の修正）
- 指数：`/v2/indices/bars/daily/topix`（TOPIX の始値・終値。営業日カレンダーとしても使う）
- 日付を指定した全銘柄の一括取得は使わない（V13 の候補銘柄の株価を取らないため）

## 用語

- 開示日 d：`DiscDate`
- t0：d より前の最後の営業日。t1：d より後の最初の営業日。t2：t1 の次の営業日
- 開示時刻に関係なく、売買は常に d の翌営業日以降に行う（場中や寄付前の開示でも同じ。保守的な扱い）
- 決算短信イベント：決算短信（`DocType` に `FinancialStatements` を含む）のうち、
  (銘柄, 期間の種類 1Q/2Q/3Q/FY, 決算期末) ごとの最初の開示。訂正などによる再開示は使わない

## 候補

### E1 会社予想に対するプラスのサプライズ

通期の **営業利益** の会社予想を基準にする。

- 本決算（FY の決算短信の最初の開示）の日：実績の営業利益 > その年度について前日以前に開示された最新の営業利益予想
- それ以外で、まだ実績が出ていない年度の通期営業利益予想が開示された日（四半期決算短信、業績予想の修正）：
  その日の最後の予想値 > 同じ年度について前日以前に開示された最新の予想値（上方修正）
- 予想値の出どころ：`FOP`（当年度の予想、年度は `CurFYEn`）と `NxFOP`（翌年度の予想、年度は `NxtFYEn`）
- 閾値は置かない（符号だけ）。営業利益の予想を出さない会社（銀行など）は対象外
- エントリー：t1 の始値（寄成）
- 根拠：日本企業は会社予想を公表し、その修正や予想比の実績が株価に遅れて織り込まれるという実証（決算発表後のドリフト、PEAD）

### E2 決算発表へのプラスの株価反応

- 決算短信イベントごとに、反応 = 銘柄の終値 t0→t1 のリターン − 同じ期間の TOPIX のリターン
- 反応 > 0 のイベントを買う（閾値は置かない）
- 反応は t1 の終値で確定するので、エントリーは **t2 の始値**（寄成）
- 根拠：決算発表時の株価反応が大きい銘柄は、その後も同じ方向に動きやすいという実証（例: Brandt et al. 2008）

### 共通

- エグジット：エントリー日を1日目として、20営業日目の終値（引成）
- エントリー日に始値がない（売買が成立しない）イベントは取らない。保有中に売買のない日は前日の終値のまま
- 調整済み価格（分割・併合を調整）を使う。配当は含まない
- 20営業日は1値だけ固定する。5日と60日は診断として並記するだけで、候補にはしない

## 損益の計算

- 30万円から複利。毎営業日、保有中のポジションに等金額で配分し、ポジションがない日は現金（0%）
- 端数株（S株など）を想定し、同時保有数に上限を置かない
- 1回あたりのリターン = 20日目の終値 × (1 − コスト) ÷ (エントリー日の始値 × (1 + コスト)) − 1
- 超過リターン = 1回あたりのリターン − 同じ期間（エントリー日の始値→エグジット日の終値）の TOPIX のリターン

## コスト

- 基本：片道0.03%（EXP-001 と同じ。寄成・引成で手数料0円の証券会社を想定）
- ストレス：片道0.10%

## 基準（ベースライン）

- B0 TOPIX の買い持ち（参考、コストなし）
- B1 306銘柄の等金額の買い持ち（参考、コストなし）
- B2 ランダム：候補がエントリーした月ごとに、同じ本数をその月にエントリーする「母集団」から無作為に選ぶ（1,000通り、seed 0..999、基本コスト）
  - E1 の母集団：E1 の符号が決まるすべてのイベント（上方・据え置き・下方、流動性の条件を満たすもの）
  - E2 の母集団：反応が計算できるすべての決算短信イベント（流動性の条件を満たすもの）

## 評価指標

損益（30万円から複利）、年率、最大ドローダウン（日次）、取引回数、1回あたり平均リターン、1回あたり平均超過リターン、
その t 値（エントリー月ごとに平均した超過リターンの月次系列で計算）、勝率、ポジションを持つ日の割合、平均同時保有数、年ごとの損益。

## 判定基準（すべて dev 期間）

候補が「有望」とされるのは、次をすべて満たす場合のみ。

1. 基本コストで損益 > 0
2. 1回あたり超過リターン（基本コスト後、対 TOPIX）の t 値 > 2
3. ストレスコストでも損益 ≥ 0
4. 基本コストの損益が B2 ランダムの95パーセンタイルを上回る

有望な候補が複数ある場合は、dev の基本コスト損益が大きい方を1つ選ぶ。
選んだ候補だけ holdout を1回見て、基本コストで損益 > 0 かつ平均超過リターン > 0 なら「追加の前向き検証に進む価値あり」とする。
holdout を見るかどうかは、dev の結果を人間が確認してから決める。
どちらも有望でなければ「推奨できる決算イベント売買なし」と結論する。

いずれの場合も、パラメータ（20営業日、符号の閾値0、営業利益、流動性1億円、コスト、期間）を結果を見て変えない。

## 診断（候補ではない。結果を見て候補に昇格させない）

- API の動作確認で、日付指定の一括取得を2回だけ実行した（`/v2/fins/summary?date=2024-05-14` の650件、`/v2/equities/bars/daily?date=2024-05-14` の4,359件）。

  1301 は V4 の300銘柄に含まれる。**9997 は V4 に含まれないため、V13 の候補から外すかどうかは人間が判断する**
