## 前提（ユーザー側の設定）

- ネットワーク: クラウド環境の設定で `api.jquants.com` への接続を許可する
- APIキー: 環境変数 `JQUANTS_API_KEY` に登録する。J-Quants API v2 は `x-api-key` ヘッダーで認証する
- キーはチャットやリポジトリに書かない。コード・ログ・コミットにも出さない

## これまでに分かっていること

- 値動きの指標だけを使ったやり方（現行AI、利確指値、保有期間の変更、夜間保有、週次リバーサル）は、どれも固定8銘柄のデータで「買って持つだけ」に勝てなかった
- 8銘柄（1570を除く7銘柄）では、リターンのほぼすべてが夜間に生じ、日中はコスト前でほぼゼロだった
- 次は値動き以外の情報として、決算イベントを試す

## 銘柄の範囲（V13 との衝突を避けるため必須）

V13 は「過去に価格の結果を見た銘柄」を候補から除外する設計である。
EXP-002 で新しい銘柄の過去価格を取得すると、V13 の候補が減るか、V13 の前提が崩れる。

そのため、V13 の銘柄選定が確定するまでは、すでに V13 から除外済みの銘柄だけを使う。

- `V4_UNIVERSE.csv` の300銘柄（v13 ブランチにある公開リスト）
- 旧8銘柄

V13 の500銘柄が確定した後は、その500銘柄以外に広げてよいかを人間が判断する。

## 進め方（EXP-001 と同じ手順）

1. データ取得のスクリプトを書き、日次株価と決算データを取得・キャッシュする。取得件数とハッシュを記録する
2. 結果を見る前に `EXP-002_PREREGISTRATION.md` をコミットする。内容は、仮説、イベントの定義、エントリーとエグジット、期間の分け方、コスト、ベースライン、判定基準
   - 例: 決算発表の翌営業日の始値で買い、N日後の終値で売る。サプライズの定義は、会社予想や前年同期との比較など
3. dev 期間だけを評価する。合格した候補が1つあるときだけ holdout を1回見る
4. 結果を `EXP-002_RESULTS.md` に、失敗も含めてすべて記録する
