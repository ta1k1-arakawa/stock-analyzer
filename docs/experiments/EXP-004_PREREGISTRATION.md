## 目的

EXP-003 の単純なルールを基準（お金を動かす方）にして、AI を使った2つの挑戦者が、これから先のデータで基準に勝てるかを比べる。
過去データの本番テスト用期間（holdout）は EXP-003 で使い切ったため、判断は前向きの成績だけで行う。

## 3つのポートフォリオ（仕組みは共通）

共通：EXP-003 と同じ306銘柄、同じ条件（流動性1億円など）、20銘柄を10組、2営業日ごとに1組を入れ替え、各組20営業日保有、寄成で売買、コスト片道0.03%、各40万円から。
開始日は全組が買う。寄付で売買が成立しない銘柄は次の候補を買う。

| 名前 | 銘柄の選び方 | お金 |
|---|---|---|
| **R ルール** | EXP-003 の合成スコア（B/P の順位＋予想ROE の順位）の上位 | 実運用（金額はユーザーが決める）。記録は40万円として計算 |
| **M LightGBM** | 開始前に学習して固定した LightGBM の予測値の上位 | ペーパー（記録だけ） |
| **L Claude** | R と同じ順位から、Claude が「割安のワナ」の可能性が高い（5段階で4以上）と判定した銘柄を除く | ペーパー（記録だけ） |

### M の中身（固定）

- 特徴量（すべて、条件を満たす銘柄の中での百分位）：B/P、予想ROE、20日・60日のリターン、250日前から20日前までのリターン、60日のボラティリティ、時価総額、売買代金、予想ROE の60日間の変化
- 目的変数：翌営業日の寄付から20営業日後の寄付までのリターンの百分位
- 学習データ：シグナル日 2017-01-04〜2026-08-26 の5営業日ごと（59,552行）。ハイパーパラメータは既定寄りの値に固定し、調整していない
- 学習後はモデルを変えない（ファイルのハッシュを毎回確認する）

### L の中身（固定）

- 流動性の条件を満たす銘柄の決算短信が出るたびに、TDnet から PDF を取り、最初の6ページを Claude（`claude-opus-5`、断られた場合は別モデルに自動で切り替え）に読ませる
- 質問：「今後3〜6か月で稼ぐ力が落ちる、または会社予想が下方修正される可能性（割安のワナ）を1〜5で」。株価の動きは考えさせない
- 評価は各銘柄の最新の決算短信のものを使う。まだ評価がない銘柄は3（どちらとも言えない）とみなす
- 開始時点ではどの銘柄も評価がないため、最初の数週間は L と R がほぼ同じになる。10〜11月の決算発表で評価がそろう

## 判定（2027-09-24 の終値で1回）

- 挑戦者（M または L）が、損益で R と TOPIX の買い持ちの両方を上回ったら「勝ち」とする
- 12か月では統計的な結論は出せない。勝った挑戦者は、次の12か月の前向き検証で「実運用の候補」にする。1回の勝ち負けで乗り換えない
- 途中経過は3か月ごとに記録するが、途中でルールやモデルを変えない

## 実運用（R）をやめる条件

- 月末の時点で、開始からの R の損益率が TOPIX の買い持ちより15ポイント以上悪ければ、実運用を止めて見直す（ペーパーの記録は続ける）

## 必要な設定（ユーザー側）

- GitHub のリポジトリの Secrets：`JQUANTS_API_KEY`（必須）、`ANTHROPIC_API_KEY`（L に必要）、`SLACK_WEBHOOK_URL`（注文の通知。既存のものを使える）
- 定期実行は既定ブランチ（main）にあるワークフローだけが動くため、このブランチを main に入れる必要がある
- L のため、実行する環境から `www.release.tdnet.info` に接続できること（GitHub Actions では通常つながる。この作業環境からはつながらず、未確認）

## 費用の見込み

- J-Quants：日次の自動更新に使う（現在の Standard のキー）。自動化の最安は Light（月1,650円）だが、Light で決算データが使えるかは未確認
- Claude API：1通あたり最初の6ページだけを読むので、年に約500〜600通で数千円程度の見込み（実際の使用量は記録して報告する）

## 注意

- 開始前に、過去の60営業日を毎日の手順で再現し、R の結果が EXP-003 の計算と1円未満の差で一致することを確かめた（1日分のデータが抜けた場合に後から追いつく動作も確認）
- M は2026-08-26 までのデータで学習したので、それ以前の期間の成績は M の実力を示さない。M の評価は開始後の成績だけで行う
- TDnet の PDF は開示後およそ30日で消えるため、自動実行が長く止まると、その間の決算短信を評価できない（その銘柄は3とみなす）
